# 숲나들e 동두천자연휴양림 예약 자동화

대상: 동두천자연휴양림 (숲나들e, `hmpgId=ID02030023`)

## 자동화 범위

| 단계 | 담당 |
|---|---|
| 1. 숲나들e 로그인 | **사용자 1회** (`npm run login`) — 이후 세션 디스크 유지 |
| 2. 사이트 구조 분석 / 조회 URL 확보 | **프로그램 자동** (`npm run inspect`) |
| 3. 예약 오픈 시각까지 대기 | 프로그램 |
| 4. 객실 자동 조회 | 프로그램 |
| 5. 우선순위 기반 객실 선택 | 프로그램 |
| 6. 예약 화면 진입 + 날짜/객실 선택 | 프로그램 (`--autofill`) |
| 7. **최종 예약 확정 / 결제** | **사용자** — 자동화하지 않음 |
| 8. 실패 시 대체 객실 + 취소분 24시간 감시 | 프로그램 |
| 9. 휴대폰 알림 | 프로그램 (텔레그램) |

7번만 사용자이고 나머지는 전부 무인 동작한다.

### 7번을 자동화하지 않는 이유

숲나들e 약관은 자동화 예약을 금지한다. 부정예약으로 판단되면 예약 취소 + 이용 제한 대상이다.
선착순 공공자원이기도 해서 자동 체결은 만들지 않는다. 그 외 전 단계는 자동이다.

### 선착순 오픈에 대한 현실적 기대치

숲나들e 공식 예약정책: 동두천자연휴양림은 **공립**, 일반 선착순은 **매주 화요일 09:00**에
6주 뒤 1주분을 **일괄 공개**한다. 우선예약은 바우처/지역주민(월요일). 1일 최대 3개 시설, 3박 4일 이내.

- 일괄 공개이므로 오픈 순간엔 "감지할 변화"가 없다. 알림이 할 일이 없다.
  → `reminderMin` 사전 알림 + `--autofill` 로 예약 화면까지 미리 진입시켜 두는 게 오픈 대응의 실체다.
- **이 도구가 실제로 이기는 구간은 취소분이다.** 환불 규정 때문에 이용일 1~2주 전과 주말 직전에
  취소가 몰리는데, 거기선 경쟁이 거의 없고 24시간 감시가 그대로 먹는다.

## 설치 (사용자 PC)

Node.js 20 이상.

```bash
cd ddc-forest-watcher
npm install              # playwright 설치
npx playwright install chromium
cp config.example.json config.json
npm test                 # 28건 통과 확인
```

## 1단계: 로그인 (1회)

```bash
npm run login
```

브라우저가 열린다. 숲나들e 로그인(본인인증 포함)을 **사람이** 완료하고 터미널에서 Enter.
세션은 `~/.ddc-forest-watcher/profile` 에 저장되고 이후 재사용된다.

## 2단계: 사이트 구조 자동 수집

```bash
npm run inspect
```

브라우저가 열리면 숙박예약 → 숲속의집/야영장 → 날짜 조회 화면까지 들어가서
**조회 월을 2~3번 바꾸고** 터미널에서 Enter. 그동안 프로그램이 전부 기록한다.

생성물 (`site-dump/`):

| 파일 | 내용 |
|---|---|
| `suggested-target.json` | **자동 추정한 조회 URL + 필드 매핑.** 이걸 `config.json` 의 `targets[0]` 에 붙인다 |
| `xhr.json` | 기록된 XHR 전체 (URL/메서드/payload/응답 일부) |
| `tables.json` | 화면 표 구조 (selector 추정용) |
| `page.html` | 최종 화면 HTML |

자동 추정이 실패하면 `site-dump/` 를 그대로 전달하면 수동으로 맞춘다.
브라우저를 조작하는 게 아니라 **요청/응답을 기록해서 설정을 역산하는** 방식이므로
로그인 정보가 외부로 나가지 않는다.

## 3단계: 설정 확인

`config.json` 에서 채울 것:

```jsonc
"watch": {
  "dates": ["2026-12-24", "2026-12-25"],   // 노리는 날짜. 비우면 전체
  "roomNameContains": [],                   // 특정 객실만
  "roomNameExcludes": [],
  "priority": ["숲속의집", "휴양관", "캠핑데크"]   // 앞쪽이 높은 우선순위
}
```

검증:

```bash
node watch.js --once -c config.json
```

`감시대상 N건 중 예약가능 M건` 이 나오면 성공. `0건`이면 필드 매핑이 틀렸다.

## 4단계: 상시 실행

```bash
node watch.js                 # 감시 + 알림
node watch.js --autofill      # 빈자리 발견 시 예약 화면까지 자동 진입
```

Windows 상시 실행은 작업 스케줄러에 "시스템 시작 시" 등록하거나 `pm2` 를 쓴다.

`--autofill` 은 `config.json` 의 `targets[0].autofill.steps` 를 따라 날짜/객실을 선택하고
**최종 확인 화면에서 멈춘 뒤** 스크린샷과 함께 알림을 보낸다. 확정은 브라우저에서 직접 누른다.

## 알림 (텔레그램)

1. 텔레그램 `@BotFather` → `/newbot` → 토큰
2. 만든 봇에게 아무 메시지 보낸 뒤 `https://api.telegram.org/bot<토큰>/getUpdates` 에서 `chat.id`
3. `config.json` → `notify.telegram` 에 입력, `"enabled": true`

## 구조

```
inspect.js          로그인 / 사이트 구조 자동 수집 + config 역산
watch.js            감시 엔진 (대기 -> 조회 -> 우선순위 선택 -> 진입 -> 알림)
src/schedule.js     오픈 스케줄·리마인더·폴링 간격 (KST)
src/parse.js        JSON/HTML 응답 -> Slot, 필터, 우선순위 정렬
src/notify.js       텔레그램/콘솔 알림, 중복 억제
src/browser.js      영구 프로필 Playwright (로그인 세션 유지)
test/               node:test 28건
```

설계상 고정된 것:

- **폴링 간격 하한 10초**가 코드에 박혀 있다 (`src/schedule.js`). 차단 방지용이라 설정으로 못 내린다.
- 매 요청에 랜덤 지터를 더해 고정 주기 패턴을 줄인다.
- `status` 가 "가능"도 "마감"도 아닌 행은 **무시**한다. 헛알림보다 누락이 낫다는 판단.
- 가능/마감 키워드가 동시에 보이면 **마감**으로 판정한다.
- 같은 슬롯은 30분 재알림 억제. 다시 마감되면 억제가 풀려 재오픈 시 또 알린다.
- 알림에 판정 근거 원문을 실어 오탐을 추적할 수 있다.

## 주의

- `config.json` 에 봇 토큰이 들어간다. `.gitignore` 등록됨. **Git 금지.**
- `~/.ddc-forest-watcher/profile` 에 로그인 세션이 들어 있다. 공용 PC에 두지 말 것.
- 폴링 간격을 억지로 낮추지 말 것. IP 차단 대상이고 실익이 없다.
